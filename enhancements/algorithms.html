Enhancement #2: Algorithms and Data Structures

Enhancements Made

The following improvements were applied across the classes in the Contact Service project:

  • Contact.java
    • Validation Logic: Enhanced input rules to handle boundary cases, e.g., names between 1–10 characters, phone numbers exactly 10 digits, and addresses up to 30 characters.
    • Robustness: Invalid data is consistently rejected, preventing runtime errors and ensuring strong data integrity.
    • Algorithm Applied: Regex validation (\\d{10}) for phone numbers demonstrates algorithmic thinking in input sanitization.
  • ContactService.java
    • Data Structure: Used a HashMap<String, Contact> for O(1) lookup, add, update, and delete operations.
    • Duplicate Detection: Throws exceptions for duplicate contact IDs, ensuring uniqueness.
    • Partial Updates: Update method allows selective updates of non-null fields, improving flexibility.
    • Scalability: These improvements allow the service to handle larger datasets efficiently.
  • ContactTest.java
    • Boundary Testing: Added tests for exact allowed limits (10-character names, 30-character addresses, 10-digit phones).
    • Parameterized Tests: Leveraged JUnit 5 @ParameterizedTest to reduce repetitive code.
    • Nested Test Classes: Organized tests into ValidContactTests and InvalidContactTests using @Nested for clarity and maintainability.
  • ContactServiceTest.java
    • Structured Tests: Reorganized into categories (Add/Delete, Update) using @Nested classes.
    • Partial Update Testing: Confirmed individual fields can be updated independently.
    • Stress Testing: Inserted 100 contacts in a loop to validate performance under larger inputs.
    • Exception Handling: Verified proper errors are thrown for non-existent contacts.

Skills Demonstrated

  • Algorithms & Data Structures: HashMap for efficient storage/retrieval, regex validation for input sanitization, and defensive programming techniques.
  • Software Testing: Applied advanced JUnit 5 features (nested, parameterized tests) to enhance coverage and readability.
  • Code Maintainability: Logical test structuring and boundary/stress testing demonstrate scalability and resilience.

Design Trade-offs and Challenges

While implementing these enhancements, I faced several challenges. Choosing HashMap provided O(1) performance but required careful management of unique keys and null checks. Using regex for phone numbers simplified validation but initially caused errors when inputs contained spaces or special characters, which I resolved by trimming input and adding error handling. Parameterized tests reduced code repetition but required restructuring nested test classes for readability. Balancing strict validation with user flexibility also required trade-offs to prevent overly restrictive input while maintaining data integrity.

Why These Enhancements Matter

These improvements significantly elevated the project:

  • Reliability: Validation ensures only correct data enters the system.
  • Performance: HashMap enables fast operations even as data scales.
  • Flexibility: Partial updates allow realistic use cases without overwriting unchanged data.
  • Testing Depth: Expanded unit tests cover normal, boundary, invalid, and large-scale scenarios, reflecting professional-level quality assurance.
