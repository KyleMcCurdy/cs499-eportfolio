Enhancement #3: Database Design and Development

Artifact Description

For this project, I enhanced the AnimalShelterCRUD Python class, which serves as the data access layer for the MongoDB database used in the animal shelter application. The original class provided basic CRUD (Create, Read, Update, Delete) functionality, and I implemented improvements to increase usability, error handling, and flexibility.

Enhancements Made

  • Connection Handling: The constructor now accepts configurable parameters (username, password, host, port, db_name, collection_name), allowing reuse in different environments and improving security by avoiding hardcoded credentials.
  • Create Operation: Added input validation to prevent empty or None values. Returns the inserted document's _id for traceability and verification.
  • Read Operation: Added an optional projection parameter to specify which fields to return, improving efficiency by reducing unnecessary data transfer.
  • Update Operation: Enhanced to support batch updates with update_many and added validation to ensure queries and new values are valid. Returns the number of documents modified for clear feedback.
  • Delete Operation: Enhanced to allow batch deletion with delete_many and validate queries before execution. Returns the number of deleted documents for confirmation.
  • Code Readability and Documentation: Added descriptive docstrings for each method, improving maintainability and usability for other developers.

Skills Demonstrated

  • Database Design & Development: Improved CRUD operations, input validation, and projection handling to ensure reliable and efficient data management.
  • Security & Error Handling: Configurable connections, input validation, and proper exception handling demonstrate secure coding practices.
  • Professional Communication: Clear docstrings and structured code make the class easier to maintain and collaborate on.

Challenges and Reflection

During the enhancement process, I faced challenges ensuring that batch updates and deletions worked correctly without unintentionally affecting other records. Validating inputs for all CRUD operations required careful testing to prevent runtime errors and maintain data integrity. I also had to design flexible connection handling to allow the class to be reused in different environments while keeping credentials secure. Through this process, I learned the importance of designing database access layers that are robust, maintainable, and efficient, and how careful validation and error handling contribute to both security and usability.
